# Purpose

Project Handover.md is the operational control document of the **Sanātana Dharma Dharohar** repository.

It serves as the operational interface between the Repository Owner, the Editorial Assistant, and the Synchronization Assistant by recording the repository's current operational state and enabling seamless continuity between working sessions.

Project Handover.md records **operational state only**. It complements, but never supersedes, the repository's governance hierarchy.

Its primary objectives are to:

- initialize AI collaborators into the current repository state;
- preserve operational continuity across sessions;
- identify the current editorial work;
- support repository synchronization;
- provide a single operational entry point into the repository.

Historical change logs belong in **Release Notes.md**.

---

# Operational Authority

Project Handover.md is the authoritative record of the repository's **current operational state**.

It enables repository continuity by recording:

- current operational status;

# AI Startup Protocol

**Purpose**

Ensure consistent repository continuity across Editorial Assistant sessions.

This protocol enables an Editorial Assistant to resume repository work with minimal context reconstruction by using **Project Handover.md** as the primary operational entry point.

---

## Startup Procedure

At the beginning of every new session:

1. Read the latest **Project Handover.md**.

2. Review the repository operating framework by consulting:

   - Project Handover.md
   - AI Editor.md
   - Codex Operating Guide.md (when synchronization is required)

3. Ask the Repository Owner:

   **Have any governance documents changed since this Project Handover was generated?**

4. If the answer is **Yes**:

   - Review the affected governance documents.
   - Re-establish repository consistency before continuing.

5. If the answer is **No**:

   - Resume directly from the **Current Work Package** defined in the **Editorial Work Queue**.

6. Throughout the session:

   - Preserve repository continuity.
   - Respect repository governance.
   - Avoid reopening settled editorial decisions without explicit instruction or new evidence.

7. Before ending the session:

   - Update **Project Handover.md**.
   - Ensure the Session Delta reflects the completed work.
   - Record any deferred editorial work.
   - Prepare the repository for synchronization.

---

# Repository Synchronization Protocol

**Purpose**

Ensure consistent synchronization between Project Handover.md and the repository.

---

## Synchronization Procedure

When synchronization is requested:

1. Read **Project Handover.md**.

2. Synchronize repository artefacts with the operational state described in this document.

3. Validate repository consistency before making updates.

4. Do not introduce new editorial or governance decisions.

5. Do not modify governance documents unless explicitly instructed.

6. Update only the sections assigned to the Synchronization Assistant.

7. Validate that the following remain mutually consistent:

   - Project Handover.md
   - Project Status.md
   - Master Candidate List.md
   - Ādhāra Śilā 108.md
   - Release Notes.md

8. Report inconsistencies rather than making assumptions.

9. Produce:

   - Synchronization Summary
   - Validation Results
   - Repository Quality Review
   - Modified Files list

# Repository Owner Workflow

**Purpose**

Define the standard workflow for maintaining repository continuity.

---

## Start of Session

1. Start a new Editorial Assistant session.

2. Share the latest **Project Handover.md**.

3. Ask the Editorial Assistant:

   **Have any governance documents changed since this Project Handover was generated?**

4. If governance documents changed:

   - Review and synchronize them first.

5. If governance documents did not change:

   - Resume directly from the **Current Work Package** defined in the **Editorial Work Queue**.

6. Complete the planned editorial work.

---

## End of Session

1. Request an updated **Project Handover.md**.

2. Replace the previous Project Handover within the repository.

3. Run the Synchronization Assistant.

4. Review:

   - Synchronization Summary
   - Validation Results
   - Repository Quality Review

5. Resolve any blocking issues.

6. Update **Release Notes.md** for the current repository version.

7. Commit the approved repository changes.
